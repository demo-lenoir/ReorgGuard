# ADR-0010: read-only operational snapshot and loopback API

Status: accepted.

The operational API reads the canonical projection through PostgreSQL. It has no writer path and no RPC-driven alternative canonical view. The server starts only in live mode when an explicit loopback `REORGGUARD_API_ADDR` is configured. Liveness is process-only; readiness combines a successful database/canonical-checkpoint read with the existing live progress state. A terminal live error leaves the API process inspectable and unready until SIGTERM.

`GET /v1/logs` uses a read-only repeatable-read transaction. The page and `sync_state.canonical_revision` come from one database snapshot. A cursor contains the last `(block_number, log_index, block_hash)` key, filter fingerprint and revision. A reorg increments the revision in the same transaction as the branch switch, so a stale cursor returns HTTP 409. Appends keep the revision and are compatible with the next page. The API returns only rows joined to canonical blocks; it never exposes an unbounded list. Page size is 1–100, with a five-second request deadline and 32 concurrent non-liveness requests. SQL substitutes NULL for payloads over 32 KiB before transmission to the API process; a selected oversized record returns HTTP 413 without altering its durable log row. Thus a page is bounded in bytes as well as row count.

Migration 002 adds `last_reorg` and `checkpoint_updated_at` to `sync_state`, plus traversal indexes for height, address and topic0. The reorg summary is written in the same transaction as the new checkpoint. `checkpoint_updated_at` changes only when a checkpoint changes; the preexisting general `updated_at` also changes for unsafe-state updates and cannot accurately represent checkpoint age. Existing installations initialize the new timestamp at migration time, after which it tracks actual checkpoint commits. The log indexes serve the explicit bounded keyset/filter query; immutable rows and canonicality constraints are unchanged.

API responses, logs, metrics and spans use fixed routes, logical endpoint IDs and finite state/reason vocabularies. They do not serialize DSNs or provider URLs. The API is unauthenticated because it is bound to loopback; any future non-loopback deployment requires a separate access-control decision. Multiple RPC providers remain data sources, never votes on canonicality.

Request context cancellation does not interrupt a backpressured socket write. The server constructor now also sets a five-second `http.Server.WriteTimeout`; the handler keeps its five-second context and 32-request cap. The socket deadline releases a held request slot when a client stops reading. A controlled blocked-connection regression exercises the same constructor used by the CLI. Liveness remains outside the 32-request semaphore.
